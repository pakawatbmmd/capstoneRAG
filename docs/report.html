Guarded Guideline Q&A

A nurse asks a question at the bedside. The system answers only from four NICE guidelines and cites the recommendation it used. If the guidelines don't cover the question, it replies exactly "Not in the guidelines". We compared seven retrieval-augmented (RAG) pipelines on 40 gold questions, half of which are deliberately not answerable.

Why it wins

  • Safety: the baseline answered 4 of the 20 undocumented questions; the chosen pipeline answered none.
  • Retrieval: keyword + meaning search, then reranking, finds the gold recommendation more often (Recall@3 0.85 vs 0.68).
  • Citations: every answer is a verified claim with a guideline, recommendation number and page.

Conditions on the verdict

  • Small test set: n = 8, so the test gap rests on 2 questions. The all-40 numbers include the 24 tuning questions.
  • Simplify (confirmed): the same pipeline without the graph, hybrid_llm, scored identically on every metric (see below), so deploy it without the graph.
  • Its errors are over-caution (6 wrongful abstentions), never unsafe answers.

Confirmatory run (post-hoc): the same pipeline without the graph

Run after the verdict, on the same 40 questions. τ and the verifier threshold were re-tuned on train only (both came out at τ 0.004, accept 0.7). It's post-hoc because the questions had already been inspected.

Safety

Five guardrails between the LLM and the nurse

Only layer 1 depends on the LLM obeying. Layers 2–5 are enforced by code, so knowledge from the LLM's memory can't reach the user without a verbatim guideline quote that supports it. Counts show what each layer did for the proposed pipeline on all 40 questions.

0

Answerability gate (before the LLM)

If the best reranker score is below τ (tuned on train), the system abstains without calling the LLM.

score · fired 1×
1

Prompt rule

"Answer only from these passages, otherwise reply Not in the guidelines." The output must be JSON: a list of claims, each with a quote and the chunk ID it cites.

soft · fired 19×
2

Verbatim quote

The quote must be at least 4 tokens and appear word for word in the cited, retrieved chunk. Otherwise the claim is fabricated.

hard rule
3

Numbers must be in the quote

Every dose, threshold or interval in the claim must appear in its quote, so "every 2 hours" can't pass when the text says 4.

hard rule
4

Entailment check (NLI)

A separate model must judge that the passage supports the claim, with confidence ≥ 0.7 (tuned on train).

model
5

Only verified claims are shown

The LLM's own prose is discarded. Any red flag (fabricated, contradicted or wrong number) blocks the whole answer. Unverifiable extras are dropped and an omission note is added.

hard · layers 2–5 blocked 6×
Data

From PDF to searchable chunks

Because chunk IDs are content hashes, re-ingesting a revised guideline re-embeds only the changed chunks. In the last rebuild, 2 chunks were re-embedded and 312 were reused, which is the basis for auto-updating guidelines.

Example chunk header

Pressure ulcers › Recommendations › 1.1 Prevention: adults › Repositioning

The header is embedded with the text, so an adult question doesn't land on the children's recommendation.

Does it fit each model?

The largest prompt is 1,545 tokens plus 1,024 output, about 1% of Qwen3-4B's 262k window. The 512-token NLI model gets a 200-word window around the quote. Only the lab's MiniLM (256 tokens) truncates: it cuts off 14% of chunks.

Storage

How the data is stored: vectors and graph

One ingest writes three files to store/nice/. Retrieval reads all three; nothing is rebuilt per question.

graph.json nodes · edgesnodes: chunk / entity · edges: mentions / is_a

Vector store: every chunk as a point in meaning-space

Each chunk becomes a 1024-number vector (bge-m3). Squashed to 2D here (PCA; the two axes keep of the variation), chunks with similar meaning sit close together. Each panel highlights one guideline in blue over the rest in grey. A question is embedded the same way, and its nearest points are retrieved.

Graph store: entities linked to the chunks that mention them

The lexicon finds medical entities in every chunk. A question's entities seed Personalized PageRank, which spreads relevance along the edges to chunks. This is the real slice for question PU01:

entity found in the questionentity the question missedparent entity (is-a)gold recommendation

Why graph-only retrieval was weak: "can't turn himself" matches no lexicon synonym for limited mobility, and "ward" pulls in a falls chunk through hospital inpatient. So the gold recommendation 1.1.9 falls outside the graph's top 5. The hybrid pipeline still finds it, ranked first, through embeddings and the reranker.

Evaluation

Results on 40 gold questions

The 40 questions were written by the team: 20 answerable, and 20 "near misses" that sound covered but aren't. They're split into train (24), val (8) and test (8). τ was tuned on train only. The test numbers after fix 1 are post-hoc, because test errors had been inspected.

What worked

  • No unsafe answers from the LLM pipeline: it answered 14 questions, all with the right recommendation retrieved.
  • Keyword and vector baselines answer what they shouldn't: they answered 15–20% of the undocumented questions.
  • Guideline@1 = 1.00 for every embedding-based pipeline: the top hit always came from the right guideline. BM25 managed 0.75.

What didn't

  • All 6 errors are over-caution: correct drafts rejected by the NLI verifier, and three retrieval misses on paraphrased questions.
  • GraphRAG added nothing measurable: hybrid and hybrid_graph differ only in third-place hits that were blocked anyway.
  • Small samples: with test n = 8, the confidence intervals overlap, so the test gap rests on 2 questions.

Limits and next steps

Path to practice

  • Licence: NICE content is licensed for study only outside the UK. Guideline text and the store are kept out of the public repository.
  • Verifier: the small NLI model rejects some correct, near-verbatim claims. A stronger judge (a larger NLI model, or Jev under a licence) is the next fix.
  • Next evidence rung: external questions from real ward nurses, then a silent trial with outputs hidden from staff.
  • Regulation: this informs a nurse's decision without driving it, so it sits in a low IMDRF category. The clinical judgement stays with the nurse.
  • Monitoring: track the abstention rate and unsafe-answer audits after every guideline update, and switch off if unsafe answers appear.
  • Data: no patient data was used. All questions are synthetic.
Glossary

Terms used in this report

RAG
Retrieval-augmented generation: look up relevant text first, then answer from it.
Chunk
A searchable piece of a guideline; here, one numbered recommendation.
BM25
Classic keyword search that scores word overlap, weighting rare words more.
Embedding
A list of numbers encoding a text's meaning; similar meanings land close together.
Cosine similarity
How close two embeddings are, from 0 (unrelated) to 1 (same meaning).
Hybrid retrieval
Keyword search plus embedding search combined, so both exact terms and paraphrases are caught.
RRF
Reciprocal rank fusion: merges result lists by rank rather than raw score.
Reranker (cross-encoder)
A model that reads the question and a passage together and scores their match more precisely.
GraphRAG
Retrieval through a graph of medical entities (drugs, conditions) and their links.
PPR
Personalized PageRank: spreads relevance from the question's entities through the graph.
Lexicon
A curated list of medical terms, synonyms and "is-a" links (e.g. apixaban is a DOAC).
τ (gate threshold)
The minimum retrieval score needed to answer; below it, the system abstains.
Abstain
Reply "Not in the guidelines" instead of answering.
LLM
Large language model; here, Qwen3-4B running locally to draft the answer.
NLI
Natural language inference: does passage A support, contradict, or say nothing about claim B?
Hallucination
A fluent statement the model invented that the source doesn't support.
Recall@3
Share of the correct recommendations found in the top 3 results.
Guideline@1
Whether the very first result comes from the right guideline.
Abstention accuracy
Share of questions where the system abstained exactly when it should have.
Unsafe answer rate
Share of undocumented questions that were answered anyway.
Train / val / test
Questions used to tune, to check, and to measure once at the end.
Post-hoc
A change made after looking at results, so its score is no longer an unbiased estimate.
Content hash
An ID computed from the text itself, so any edit gives a new ID.
Jev
TypeSafe's model that returns calibrated yes/no and choice judgements; used in the side study.
